# ADR-0008: 이스케이프 책임을 렌더 계층으로 단일화, PDF 요청을 POST 로 전환

날짜: 2026-07-21 / 상태: accepted
관련: ADR-0007(이스케이프 단일화 선언)의 실제 이행, ADR-0005(NFR-6) 보강, ADR-0001(PDF 엔드포인트) 계약 변경

## Context

아키텍처 감사에서 A급 결함 3건이 나왔고, 그중 둘은 문서가 "이미 해결됐다"고 선언한 사안이 실제로는 미이행이었다.

**이스케이프**: ADR-0007이 "escape 를 `llm._normalize` 한 곳으로 단일화"했다고 기록했으나, 실제로는 저장 계층(`html.escape`)과 렌더 계층(Jinja2 autoescape)에 이중으로 걸려 있었다. 결과가 눈에 보이는 형태로 드러났다 — 아이가 가져갈 A5 인쇄물에 `두꺼비가 &quot;괜찮아!&quot; 하고 외쳤어. 콩쥐 &amp; 두꺼비는...`처럼 엔티티가 문자 그대로 찍혔다. 기존 테스트가 API JSON 응답만 검사해 PDF 렌더 결과를 보지 않았기 때문에 통과 상태로 방치됐다.

**아동 이름**: ADR-0005가 "DB 저장·로그 기록 금지"를 명시했으나, `author_name` 을 쿼리스트링으로 받아 uvicorn 액세스 로그에 그대로 기록되고 있었다. DB 미저장만 이행된 절반짜리 상태였다.

## Decision

**1. 이스케이프 책임은 렌더 계층에만 둔다.** 저장 시점(`llm._normalize`, `data4library`)의 `html.escape` 를 제거하고, DB·API 응답은 raw 텍스트를 다룬다. HTML 이스케이프는 Jinja2 autoescape(PDF)와 `textContent`(DOM)가 각자의 출력 맥락에서 한 번씩만 수행한다. 이스케이프는 데이터의 성질이 아니라 특정 출력 맥락의 요구이므로, 저장 계층이 그 책임을 갖는 순간 출력 맥락이 둘 이상이 되면 반드시 어긋난다.

XSS 방어는 유지된다 — `<script>` 가 든 구술은 HTML 소스에서 escape 되어 실행되지 않고 문자로만 출력된다. 이를 검증하는 회귀 테스트를 추가했으며, 검증 대상은 API JSON 이 아니라 **실제 렌더된 PDF 의 추출 텍스트**다.

**2. PDF 요청을 `POST /api/sessions/{id}/pdf` 로 전환한다.** 아이 이름을 요청 바디로 받아 URL·액세스 로그·브라우저 히스토리 어디에도 남기지 않는다. `GET` 은 오프라인 폴백(`id="demo"`, ADR-0004 3계층) 전용으로 남기고, 숫자 세션 id 로 GET 이 오면 400 과 함께 POST 사용을 안내한다. 추가로 uvicorn 액세스 로그에 쿼리스트링 전체를 마스킹하는 필터를 넣어, 향후 어떤 파라미터가 추가돼도 자동으로 보호되게 한다.

**3. 프론트 generate 타임아웃을 35초로 올린다.** 백엔드가 15초 × 2회(ADR-0004)로 최대 30초를 쓰는데 프론트가 20초에 중단해, 재시도가 성공해도 사용자는 항상 실패 화면을 봤다. 1계층 폴백이 실질적으로 무력화된 상태였다.

**4. CI 를 도입한다.** ruff · pytest · Chromium 실렌더 · gitleaks · pip-audit. Chromium 을 CI 에 설치해 실제로 PDF 를 렌더하는 이유는 ADR-0006 이 짚은 리스크(배포 빌드에서 chromium 설치 누락 시 PDF 만 조용히 실패) 를 배포 전에 잡기 위해서다.

## 기각 대안

- **저장은 escape 유지 + 렌더 계층에서 unescape**: 복잡도만 늘고 어느 계층이 진실인지 더 모호해진다.
- **`author_name` 을 헤더로 전달**: 로그 노출은 막지만 프론트가 어차피 fetch+blob 으로 바뀌어야 해 POST 바디 대비 이점이 없다.
- **액세스 로그 전체 비활성화**: 디버깅 능력을 잃는다. 쿼리스트링만 마스킹하는 편이 손실이 적다.
- **`gitleaks-action@v2`**: PR 커밋 목록을 GitHub API 로 조회해 `pull-requests` 권한이 필요하고(없으면 403), 조직 계정에서는 라이선스 키를 요구한다. 바이너리 직접 실행으로 대체했다.

## Consequences

- 긍정: 인쇄물 품질 결함이 제거됐다. 아동 개인정보가 저장·URL·로그 어디에도 남지 않아 "수집하지 않는다"고 말할 수 있다. 테스트가 5 → 15건으로 늘며 PDF 렌더·LLM 재시도·정보나루 성공 경로·`lang=en` 이 처음으로 검증 범위에 들어왔다.
- 부정: PDF 다운로드가 새 탭 열기에서 blob 다운로드로 바뀌어, 브라우저가 다운로드 확인을 띄울 수 있다. 키오스크·태블릿 환경이라면 실물 확인이 필요하다.
- 리스크: 액세스 로그 마스킹 필터가 uvicorn 의 `record.args` 5-튜플 포맷에 의존한다. uvicorn 이 포맷을 바꾸면 예외 없이 조용히 무력화된다.
- 리스크: 앞단에 nginx 등 프록시를 두면 그쪽 액세스 로그는 별도 정책이 필요하다. 다만 이름이 URL 에 실리지 않게 됐으므로 실효 위험은 사라졌다.
- 교훈: **문서에 "해결됨"이라고 적는 것과 실제 이행은 다르다.** ADR-0007 의 이스케이프 단일화, ADR-0005 의 로그 금지가 모두 선언만 되고 코드에 반영되지 않은 채 통과했다. 결함이 드러난 경로는 둘 다 "테스트가 그 계층을 보지 않았다"는 공통점을 갖는다 — 이후 ADR 에 이행 조건을 쓸 때는 그것을 검증하는 테스트를 함께 명시한다.
