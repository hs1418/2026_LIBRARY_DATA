# ADR-0003: 배포 플랫폼 — Render 채택

날짜: 2026-07-06 / 상태: accepted

## Context

공모전·포폴용 프로젝트, 기한 2026-08-02(내부마감). 배포 목적은 24/7 운영이 아니라 **제출 자료(원고 첨부 링크)·시연 영상 녹화용** — 원고 제출 시점과 녹화 세션 시점에만 살아있으면 됨. 워크숍 당일 실제 운영은 로컬 실행이 원칙이라 이 배포는 운영 경로가 아님. 팀 3인 중 배포·인프라 전담자 없음(개발자 1인이 겸임), 설정 시간 최소화가 우선.

## Decision

**Render**를 배포 플랫폼으로 채택. FastAPI 앱 + Postgres addon을 git push로 배포. 무료 티어의 콜드스타트(비활성 후 슬립)는 이 프로젝트 목적(상시 접속 아닌 특정 시점 접속)에서 실질적 문제가 되지 않음 — 녹화·제출 전 접속 1회로 깨워두는 것으로 해소.

## 기각 대안

- **Railway**: 무료 크레딧이 시간 단위로 소진되는 방식이라, 마감 근처에 예기치 않게 서비스가 멈출 리스크(과거 EC2 과금 사고와 유사한 "무료인 줄 알았는데" 함정) — Render의 슬립 방식이 이 용도에 더 안전.
- **Fly.io**: flyctl CLI·Dockerfile 직접 관리가 필요해 설정 복잡도가 이 규모·기한에 안 맞음.
- **Supabase**: 매니지드 DB+인증+스토리지 묶음이나, 이 프로젝트는 인증·스토리지를 안 씀 — DB만 쓰려고 서비스를 하나 더 늘이는 손해. 게다가 FastAPI 앱 자체를 호스팅해주지 않아 별도 플랫폼이 또 필요.
- **EC2+Docker+Nginx (AI-DO 재사용)**: 과거 t3.micro/리전 실수로 과금 사고 재발 리스크, 시간 여유 없음. 이 프로젝트 규모(동시 사용자 0)엔 명백한 과설계.

## Consequences

- 긍정: 설정 시간 ~1시간, 과금·리전 실수 리스크 구조적으로 낮음, git push만으로 갱신.
- 부정: 무료 티어라 첫 요청 지연(콜드스타트) 발생 — 상시 서비스로는 부적합(단, 이 프로젝트엔 무관).
- 리스크: 녹화·제출 직전 "배포 상태 확인" 체크포인트를 빠뜨리면 접속 안 되는 상태로 마주칠 수 있음 — PLAN.md W4~W5 일정에 명시적 태스크로 포함해 대응.
