# ADR-0007: LLM 공급자 — Gemini에서 Groq/Llama 3.1로 교체, 추천 문구 생성 제거

날짜: 2026-07-21 / 상태: accepted
관련: ADR-0001(LLM 배관), ADR-0002(추천 파이프라인)의 일부를 대체

## Context

백엔드 뼈대는 Gemini를 가정한 placeholder로 구현돼 있었고, 프롬프트는 "AI담당자 교체 자리" 주석으로 비워둔 상태였다. W2 핸드오프로 AI담당자가 실제 산출물을 전달했다: Groq/Llama 3.1(`llama-3.1-8b-instant`) 기반 동화 생성 프롬프트 v1.2, 정보나루 추천 모듈, 폴백 도서 5권, 콩쥐팥쥐 서지 시드. 공급자가 Gemini가 아닌 Groq이고, 산출물에 추천 문구(comment) 생성기가 포함되지 않았다.

## Decision

**LLM 공급자를 Groq/Llama 3.1로 교체한다.** AI담당자의 프롬프트(system·user)를 한 글자도 변형하지 않고 이식하며, 프롬프트 수정 권한은 AI담당자에게 둔다(코드 주석으로 명시). 파라미터도 원본 유지: `response_format=json_object`, `temperature=0.5`(고유명사 환각 억제 목적).

배관은 우리 책임으로 덧입힌다 — `asyncio.wait_for` 15초 + 1회 재시도(ADR-0004), 네트워크 경계를 `_call_groq` 단일 함수로 분리해 실키 없이 테스트 가능하게 유지.

**HTML 이스케이프를 `llm._normalize` 한 곳으로 단일화한다.** AI팀 원본은 생성 함수 내부에서 `html.escape`를 걸지만, 우리 파이프라인도 같은 처리를 하고 있어 그대로 두면 `&amp;lt;`처럼 이중 이스케이프되어 화면·PDF에 깨진 문자가 노출된다. 원본의 escape 호출을 제거하고 우리 지점만 남겼으며, 회귀 방지 테스트를 추가했다.

**추천 문구(comment) 생성을 제거하고 `null` 고정한다.** ADR-0002는 정보나루 검색 결과를 LLM에 다시 넣어 추천 문구를 만드는 2차 호출을 포함했으나, AI담당자 산출물에 해당 생성기가 없다. 없는 기능을 우리가 임의로 만들면 프롬프트 권한 분리가 무너지므로 필드만 남기고 값은 비운다.

**추천 폴백의 진실 소스를 시드로 일원화한다.** 서비스 모듈 상수(`FALLBACK_BOOKS`)와 DB 시드(`Story.recommend_books`)가 중복되므로, 서비스는 시드를 우선 조회하고 시드가 비었을 때만 모듈 상수를 쓴다.

## 기각 대안

- **Gemini 유지 + AI팀 프롬프트만 이식**: 프롬프트 v1.2는 Llama의 JSON 모드·온도 특성에 맞춰 튜닝됐고, AI담당자가 Groq 키를 발급해 전달했다. 공급자를 바꾸면 그쪽 검증 결과가 무효가 된다.
- **추천 문구를 우리가 작성**: 프롬프트는 AI담당자 소관이라는 역할 분리를 깨고, 톤이 갈릴 위험이 있다. 필요하면 AI담당자가 생성기를 추가하는 것이 옳은 경로.
- **이스케이프를 양쪽에 두고 서비스 경계에서 unescape**: 복잡도만 늘고 실수 여지가 크다.

## Consequences

- 긍정: 프롬프트 권한이 AI담당자에게 명확히 귀속돼 튜닝 사이클(W3)이 우리 코드 수정 없이 돈다. Groq은 추론 속도가 빨라 NFR-2(15초 내 생성)에 유리하다.
- 부정: 계약 이행을 위해 스코프 밖 3파일(schemas·routers 2개)을 수정했다 — 응답 스키마 확장, `intro_summary` 전달, comment null 고정. 전부 최소 배관이며 로직 변경은 아니다.
- 리스크: 배포 환경변수를 `GEMINI_API_KEY`에서 `GROQ_API_KEY`로 교체해야 한다(코드 밖 설정, Render 대시보드). W4 배포 점검 항목에 포함.
- 리스크: 시드의 `intro_summary`에 "단독에 물 채우기"("밑 빠진 독"의 오기로 추정)가 있다. AI담당자 도메인 데이터라 임의 수정하지 않았고 확인을 요청한다.
- 리스크: `llama-3.1-8b-instant`는 8B 소형 모델이라 한국어 동화체·고유명사 유지 품질이 W3 튜닝의 핵심 변수가 된다. 실측 후 모델 상향(70B 등)을 재검토할 수 있다.
