# ADR-0002: 개인화 추천 재도입 (키워드→정보나루→LLM, 세션 범위)

날짜: 2026-07-06 / 상태: accepted

## Context

앞선 논의(2026-07-05)에서 "개인화 없이 이야기별 고정 큐레이션"으로 정했으나, 그러면 정보나루 API가 "잊힌 이야기 발굴"(사전 분석)에만 쓰이고 런타임엔 안 쓰여 적합성 40점(도서관 데이터 활용)이 약해지는 문제가 드러남. "세션 내 개인화"는 로그인·아카이빙 없이도 가능(그 자리 입력에 따라 결과만 달라짐, 상태 영속 없음)하다는 점을 구분.

## Decision

영수증 추천도서를 **키워드→정보나루→LLM** 방식으로 재설계. `generate` LLM 응답에 아이 구술 기반 키워드를 함께 출력 → 그 키워드로 정보나루 API 도서 검색 → 검색 결과를 LLM에 다시 넣어 이 아이 맞춤 추천 문구 생성. 정보나루 호출·LLM 2차 호출 실패 시 `Story.recommend_books`(이야기별 고정 5권)로 폴백. API `GET /api/sessions/{id}/recommendations` 확정(보류→승격).

개인화는 **세션 범위 한정** — 로그인·계정·프로필·아카이빙·히스토리 누적은 도입하지 않음. Session은 그 세션 결과만 담고 영속 조회 불필요.

## 기각 대안

- 이야기별 고정 큐레이션 단독(ADR 이전 결정): 정보나루가 런타임에 안 쓰여 적합성 약함 — 폴백으로 강등해 유지.
- 사용자 계정 기반 개인화(히스토리 누적): 로그인·아카이빙 필요, MVP 스코프 초과 — 세션 범위 개인화로 충분.

## Consequences

- 긍정: 정보나루 API가 핵심 흐름에서 실제로 작동 → 적합성 직결. "창작→독서 순환" 서사가 진짜가 됨. 아이 상상에 따라 추천이 달라지는 실개인화.
- 부정: 런타임 실패 지점 2개(정보나루 호출·LLM 2차 호출) 추가. W3 AI담당자 작업량 증가.
- 리스크: 정보나루 지연·장애 시 추천 단계 지연 — 고정 추천 폴백으로 방어(그래서 Story.recommend_books 삭제 안 함).
