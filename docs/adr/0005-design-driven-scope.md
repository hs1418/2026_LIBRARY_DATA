# ADR-0005: 디자인 목업 반영 — 페이지 분할·언어 선택 도입, 이메일 전송·전광판 컷

날짜: 2026-07-16 / 상태: accepted
관련: ADR-0001의 `Session.generated_ko/generated_en` 단일 필드 설계를 대체

## Context

디자이너가 완성 목업(화면 5개 + 영수증 모달, 고려청자 팔레트)을 전달했다. 대조 결과 ADR-0001·0002에 없던 요소 5개가 발견됐다: ① 언어 선택 화면, ② PDF 미리보기의 **페이지별 분할**, ③ 이메일 PDF 전송 폼, ④ "도서관 오프라인 전광판으로 전송" 문구, ⑤ 꼬마 작가 이름. 팀 3인·내부마감 2026-08-02 제약에서 전부 수용하면 스코프가 무너지므로 선별이 필요하다.

## Decision

**수용 2개**

1. **페이지 분할** — LLM이 뒷이야기를 3~5페이지로 나눠 반환한다. `Session.pages` JSONB(`[{no, ko, en}]`)가 ADR-0001의 `generated_ko`/`generated_en` 단일 필드를 대체한다. 서버에서 문자열을 자르면 문장이 어색하게 끊기므로 분할 판단을 LLM에 맡긴다.
2. **언어 선택** — 화면1에서 ko/en 선택, `POST /generate`에 `lang` 파라미터 추가, `Session.lang` 저장. 한/영 병기 자체는 기존 결정이라 파이프라인 변경 없이 주 언어만 지정하는 수준.

**컷 2개**

3. **이메일 PDF 전송 폼 삭제** — SMTP 인프라 신규 도입 + 개인정보(이메일) 수집이 필요한데, 워크숍은 현장 프린트가 원칙이라 이미 대체 경로가 있다.
4. **"전광판으로 전송" 문구 삭제** — 디지털 아카이브·전송은 2026-07-05에 컷된 기능이다. 구현하지 않는 동작을 UI가 수행했다고 표시하면 시연 중 허위 진술이 된다.

**조건부 1개**

5. **아이 이름** — PDF 렌더링 요청 파라미터(`?author_name=`)로만 사용하고 DB 저장·로그 기록을 하지 않는다. 아동 개인정보를 보관하지 않기 위함이며, 책에 이름을 넣는 목적은 이것으로 충분히 달성된다.

## 기각 대안

- **목업 전체 수용**: 이메일 전송만으로 SMTP 연동·전송 실패 처리·개인정보 동의 절차가 붙어 4주 스코프를 넘긴다.
- **페이지 분할을 서버 로직으로 구현**(문자 수 기준 등): 문장 중간이 잘려 그림책 품질이 떨어진다. 어차피 LLM을 호출하므로 분할까지 맡기는 편이 비용 증가 없이 품질이 높다.
- **아이 이름 DB 저장**: 워크숍 종료 후 조회할 일이 없어 저장 이득이 없는데, 아동 개인정보 보관 책임만 생긴다.

## Consequences

- 긍정: 목업과 구현의 불일치가 사라져 디자인·개발이 같은 그림을 본다. 개인정보를 아예 보관하지 않아 아동 대상 서비스의 리스크가 구조적으로 제거된다.
- 부정: AI담당자의 프롬프트 사양이 바뀐다 — 단일 문자열이 아닌 `pages[]` JSON 반환. W2 핸드오프 전에 전달해야 한다.
- 리스크: 페이지 분할 품질(문장이 페이지 경계에서 자연스러운가)이 W3 튜닝 사이클의 새 검수 항목이 된다.
